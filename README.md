# Task Tracker Pro Enterprise 3.0

تحويل التطبيق من صفحة HTML تعتمد على LocalStorage إلى نظام مؤسسات مع Backend وPostgreSQL ومصادقة JWT وصلاحيات RBAC وتحديث لحظي عبر WebSockets.

## التشغيل السريع (Docker)

انسخ `.env.example` إلى `.env` وضع قيمة `JWT_SECRET` عشوائية وفريدة لا تقل عن 32 حرفاً قبل التشغيل. لا تستخدم القيمة النموذجية كما هي.

```bash
docker compose up --build
```

افتح [http://localhost:4000](http://localhost:4000)

تُنشأ حسابات التهيئة بواسطة الخادم عند أول تشغيل. لا تعرض بياناتها في الواجهة أو تشاركها؛ غيّر كلمات مرورها من إعدادات المدير بعد تسجيل الدخول الأول، واستخدم حساباتك المؤسسية في بيئة الإنتاج.

## التشغيل المحلي بدون Docker

1. انسخ ملف البيئة:

```bash
copy .env.example .env
```

2. يستخدم الإعداد الافتراضي قاعدة PGlite محلية وذاكرة مؤقتة داخل الذاكرة. لاستخدام PostgreSQL، أنشئ قاعدة `task_tracker` ومستخدم `tracker` ثم غيّر `DATABASE_URL` في `.env` إلى بيانات اتصال قاعدة PostgreSQL. Redis اختياري.
3. ثبّت الحزم وشغّل الخادم:

```bash
cd backend
npm install
npm start
```

الجداول والمهام الثلاثون تُزرع تلقائياً عند أول تشغيل.

### التشغيل التلقائي في Windows

شغّل `install-autostart.bat` مرة واحدة من مجلد المشروع. يسجل مهمة مجدولة لحساب Windows الحالي لتشغيل الخادم في الخلفية عند تسجيل الدخول، ويشغّله فوراً لأول مرة. يتطلب Node.js وملف `.env` والاعتماديات؛ يثبت البرنامج الاعتماديات تلقائياً عند غيابها. افتح `http://localhost:4000`، وتوجد سجلات التشغيل في مجلد `logs`.

لإزالة التشغيل التلقائي شغّل:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\uninstall-autostart.ps1
```

## لوحة التحكم التنفيذية

- ملخص لأداء المهام مع فصل معدل المهام المكتملة عن متوسط التقدم الفعلي.
- مؤشرات للمهام قيد التنفيذ والحرجة والمتأخرة، والميزانية مع نسبة الإنفاق.
- يُحسب معدل الإنجاز ومتوسط التقدم على المهام غير الملغاة، بينما يقيس الالتزام بالموعد المهام المفتوحة فقط؛ لا تدخل المهام المكتملة أو الملغاة في مقام معدل الالتزام.
- تُحسب فروق الميزانية على مستوى السنتيم لتفادي أخطاء الكسور العشرية العائمة، وتُعرض القيم المالية بمنزلتين عشريتين.
- بطاقات إجراءات مباشرة للمهام الحرجة أو المحجوبة والمتأخرة والمستحقة خلال 7 أيام.
- قائمة بأهم المهام التي تتطلب متابعة، مع فتح تفاصيل المهمة مباشرة.
- عرض Kanban بأعمدة زجاجية عائمة قابلة للتمرير، مع مساحة مستقلة للبطاقات داخل كل مرحلة.
- مركز إشعارات داخل التطبيق للمهام المتأخرة وقريبة الموعد والحرجة والمتجاوزة للميزانية، مع إشعار عند تغييرات المهام. تحفظ الإشعارات محلياً لكل مستخدم على الجهاز، ويمكن فتح المهمة المرتبطة أو تحديد الإشعارات كمقروءة ومسحها.
- يمكن للمدير استيراد نسخة JSON الاحتياطية؛ تُضاف المهام الجديدة وتُحدّث المهام المطابقة بمعرّفها بعد التحقق من البيانات، بحد أقصى 500 مهمة للملف.
- صفحة إعدادات للمدير لإدارة المستخدمين والأدوار والأقسام والحسابات النشطة، وتغيير كلمة المرور، وتحرير قوائم الأقسام والمواقع وأنواع الأعمال والحالات والأولويات، مع تنزيل النسخة الاحتياطية.
- تقرير ميزانيات وإنفاق حسب شهر الاستحقاق قابل للطباعة أو الحفظ كـ PDF، مع ملخص الميزانية والإنفاق وتفصيلها حسب المهمة والقسم. لا يمثل الإنفاق حركة شهرية؛ بل الإجمالي المسجل حالياً لكل مهمة، لعدم وجود سجل معاملات مالية مؤرخ.

## طبقات النظام

- **API:** Node.js + Express — REST تحت `/api`
- **قاعدة البيانات:** PostgreSQL مع قيود ACID
- **التخزين المؤقت:** Redis مع سقوط تلقائي إلى الذاكرة إن تعذر الاتصال
- **المصادقة:** JWT (رأس Authorization + كوكي HttpOnly)
- **الصلاحيات:** Admin / Department Manager / Assignee
- **اللحظي:** Socket.io لتحديث Kanban والمهام لدى كل المتصلين
- **التنبيهات:** SMTP وSlack وTelegram وFCM عبر متغيرات البيئة (اختيارية)

## الأمان

- استعلامات PostgreSQL مُعلَّمة ضد SQL Injection
- Helmet + Rate limiting + تعقيم المدخلات ضد XSS
- في الإنتاج فعّل HTTPS (عكس Nginx/ALB) وضَع `JWT_SECRET` قوياً
- نسخ احتياطي يومي مقترح: `pg_dump` عبر cron أو AWS RDS automated backups

## النشر السحابي

ضع نفس خدمات `docker-compose` على AWS ECS/Fargate أو Cloud Run + Cloud SQL أو Azure Container Apps، مع PostgreSQL مُدار وRedis (ElastiCache / Memorystore) وشهادة TLS على الموزّع.
